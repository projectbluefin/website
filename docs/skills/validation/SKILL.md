# Validation skill

Use this skill when validating changes to this repository.

1. This repository is a static site built with Vite, Vue 3, and Tailwind CSS.
2. The gate check in CI (`test` job in `.github/workflows/ci.yml`) runs:
   - `npm run lint` (ESLint with `@antfu/eslint-config`)
   - `npm run typecheck` (`vue-tsc --noEmit`)
   - `npm run test:run` (`vitest run`)
   - `npm run build` (`vite build`)
3. All four steps must pass cleanly with zero errors before a change can merge.
4. Changes that modify dependencies in `package.json` must be accompanied by an
   updated `package-lock.json` generated by `npm install`.
5. Do not edit `package-lock.json` by hand.
6. When updating dependencies, run the full validation suite locally before
   submitting: `npm run lint && npm run typecheck && npm run test:run && npm run build`.
7. Keep `package-lock.json` in sync with `package.json` at all times. Workflows
   (`deploy.yml`, `preview.yml`, `update-content.yml`) use `npm ci` rather than
   `npm install` to guarantee byte-for-byte fidelity with `package-lock.json`.
8. For live-data cache updates, keep the cached file path list identical in order and content across `update-content.yml` (restore and save), `deploy.yml` (restore), and `preview.yml` (restore).
9. When modifying a Vue component under `src/components/`, check `src/tests/` for existing component unit tests and keep test assertions aligned with the runtime contract.
10. For CI concurrency changes, keep pull-request runs grouped by PR and non-PR runs unique; `scripts/tests/workflow-concurrency.test.ts` checks cancellation and group isolation. Assert the parsed YAML expressions directly instead of executing them as JavaScript.
11. For an ESLint or `@antfu/eslint-config` upgrade, move both packages in one
    change (each major of the config pins the ESLint major it accepts), and
    check that `npm run lint:fix` changed only layout: compare each touched
    file with all whitespace stripped against `HEAD`. Turn off a new rule
    whose auto-fix rewrites code (for example `e18e/prefer-object-has-own`,
    which needs a newer `lib` than `tsconfig.json` sets) instead of letting
    the reformat carry it. Lore bodies render Markdown heading markers as
    literal text, so a `markdown/heading-increment` fix changes what the
    audience reads; keep it to the marker itself.
12. Renovate's npm pin (`constraints.npm` in `renovate.json`) must match the npm CI runs, which is the one bundled with Node (`node-version: '26'` → npm 11). With npm 12, Renovate's lock-file updates failed (#1009, `EALLOWREMOTE`). Renovate doesn't offer updates to the pin, so a Node major PR that brings a newer npm fails `scripts/tests/npm-constraint.test.ts` with the exact value to set. Fix it by raising `constraints.npm` in that same PR, not by editing or skipping the test.

Documentation-only check:

Changes that touch ONLY files matching `docs/**` or `*.md` skip the application
test suite and build in CI; only actionlint and markdown checks run.
Do not run the full application suite for documentation-only changes.
